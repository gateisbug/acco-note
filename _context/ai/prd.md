# acco-note AI 제안 요구사항 (초안)

> 아래 항목은 **AI 제안**입니다. 사용자 확인 전까지 `_context/user/prd.md`의 요구사항으로 간주하지 않습니다. 논의 중 확정된 사항은 별도로 표시하며, 사용자 요구사항 문서를 기준으로 합니다.

## 우선순위 높음 — 기본 사용성

### A-01. 거래 내역 CRUD 및 입력 필드
- **확정:** 지출/수입 내역의 작성, 수정, 삭제를 지원합니다.
- **확정:** 날짜, 유형(지출/수입), 금액, 내역명은 필수이며 카테고리, 메모, 지출 결제수단은 선택입니다.
- 금액 유효성 검사와 입력 누락 안내 UI를 제안합니다.
- **확정:** 일반 거래는 삭제 확인창에서 확인한 후 삭제하고 관련 통계·예산 집계에서 즉시 제외합니다. 취소 시 거래와 집계를 유지합니다. 고정지출 생성 거래는 A-07의 회차 처리 규칙을 적용하며 환불 연결 원거래는 확인창에서 환불도 함께 삭제됨을 안내하고, 확인하면 원거래와 연결 환불을 함께 삭제하여 집계를 갱신합니다. 취소하면 모두 유지합니다.
- **확정:** 거래 금액은 원화 정수로 1원 이상 입력하며 0원·음수·소수 금액은 허용하지 않습니다. 수입·지출은 유형으로 구분하고 환불은 원래 지출에 연결하여 별도로 기록합니다.
- **확정:** 미래 날짜의 수입·지출은 입력할 수 있으며 예정 거래로 저장합니다. 확정 전에는 실제 수입·지출 통계 및 예산 사용액에 포함하지 않습니다.
- **확정:** 일반 예정 거래와 고정지출은 해당 날짜에 사용자 확인 없이 자동 확정합니다. 앱 미실행 중 도래한 항목은 다음 실행 시 원래 예정일의 거래로 반영하며 중복 반영하지 않습니다. 건너뛴 고정지출 회차는 제외합니다.
- **확정:** 기기의 현지 시간대와 관계없이 한국 시간(Asia/Seoul)을 기준으로 예정일 00:00부터 자동 확정 대상이 됩니다.
- **확정:** 일반 거래의 날짜 변경 시 한국 시간 기준 미래 날짜는 예정으로 전환하여 실제 집계에서 제외하고, 오늘·과거 날짜는 확정하여 변경된 날짜의 집계에 반영합니다.
- **결정 필요:** 날짜 기본값과 과거 날짜 신규 입력 정책, 환불 연결 거래 및 고정지출 생성 거래의 날짜 변경, 환불 기록 자체의 수정·삭제, 삭제 후 복구 지원 여부.

### A-02. 카테고리 관리
- **확정:** 지출 및 수입 카테고리를 분리하며 하위 분류 없이 1단계로 구성합니다.
- **확정:** 기본 카테고리를 제공하고 사용자가 직접 추가·수정할 수 있습니다. 기존 내역에서 사용 중인 카테고리는 보관 처리하여 기존 내역을 유지하고 신규 선택에서 제외합니다.
- 카테고리별 합계와 비중을 조회할 수 있도록 제안합니다.
- **결정 필요:** 기본 카테고리 목록, 미사용 카테고리 삭제 및 보관 해제 지원 여부.

### A-03. 결제수단 관리 확장
- **확정:** 사용자가 '현금', '생활비 카드' 등 직접 이름을 붙여 결제수단을 등록·수정합니다. 기존 내역에서 사용 중인 결제수단은 보관 처리하여 기존 내역을 유지하고 신규 선택에서 제외합니다.
- **확정:** 지출 작성 시 결제수단 선택은 선택 사항입니다.
- 기간별 사용액/사용 횟수/비중 집계를 제안합니다.
- 카드 사용의 **기록과 분석**이 목적이며 카드 연동/실제 결제 처리는 제외합니다.
- **결정 필요:** 이름과 별도인 유형 구분의 필요 여부, 미사용 결제수단 삭제 및 보관 해제 지원 여부.

### A-04. 날짜 기반 탐색 및 검색·필터
- 달력과 목록에서 날짜를 탐색하고, 날짜별 내역 및 합계를 확인합니다.
- 기간, 수입/지출, 카테고리, 결제수단, 키워드로 필터링할 수 있도록 제안합니다.
- **결정 필요:** 기본 진입 화면(달력/목록/대시보드).

## 우선순위 중간 — 재무 관리 및 분석

### A-05. 예산 관리
- **확정:** 월별 전체 지출 예산과 선택적인 카테고리별 한도를 설정하고, 사용액/잔여액/초과액을 표시합니다. 실제 지출만 사용액에 포함하고 고정지출 예정액은 별도로 표시합니다.
- **확정:** 저축 목표는 목표명·목표금액·시작일·목표일을 설정하며 여러 목표를 지원합니다. 목표별로 직접 기록한 저축 금액으로 진행률을 계산하고 수입·지출 통계에 중복 반영하지 않습니다.
- **결정 필요:** 전체 예산과 카테고리 한도의 관계, 예산 이월, 환불 반영 시점, 저축 기록 수정·삭제 및 인출, 목표 완료 후 관리.

### A-06. 통계·비교 분석
- 기간별 총수입, 총지출, 차액을 요약합니다.
- 일/주/월 추이와 직전 기간 비교, 카테고리별·결제수단별 비중을 제공합니다.
- **결정 필요:** 주 시작 요일, 차트 종류, 비교 기준과 집계 제외 규칙.

### A-07. 고정지출의 실제 반영 방식
- 반복 규칙(매월 N일 등)과 예상 지출을 별도 목록으로 관리합니다.
- **확정:** 예정일 전에는 예정으로 표시하고 해당 날짜에 자동으로 실제 지출로 등록합니다. 자동 확정 전에는 실제 지출로 집계하지 않습니다.
- **확정:** 특정 회차 건너뛰기, 자동 확정 전 회차 금액 변경과 확정 후 거래 금액 정정, 같은 회차 중복 등록 방지를 지원합니다.
- **확정:** 자동 생성된 거래를 삭제하면 통계·예산에서 제외하고 해당 회차를 '건너뜀'으로 처리하여 자동 재생성을 방지합니다. 반복 설정과 이후 회차는 유지합니다.
- **결정 필요:** 반복 주기, 말일 처리, 반복 설정 변경의 적용 범위, 건너뛰기 취소.

## 우선순위 높음 — 로컬 데이터 안전성

### A-08. 내보내기·가져오기 검증 및 복구
- JSON 내보내기에 데이터 형식 버전(schemaVersion)을 포함합니다.
- **확정:** 가져오기 전 JSON 구조와 값의 유효성을 검증하고, 대체 내용을 보여준 뒤 사용자 확인을 받아 적용합니다. 검증 또는 적용 실패 시 기존 데이터를 유지하고 오류를 안내하며 일부만 대체된 상태를 남기지 않습니다.
- 브라우저 저장 데이터 삭제 및 기기 변경 시 데이터 유실 가능성을 안내합니다.
- **확정:** Import 시 기존 데이터를 전체 대체하며 병합은 지원하지 않습니다.
- **결정 필요:** 대체 전 백업 및 백업 리마인더 필요 여부.

### 환불·취소 처리 — 사용자 요구사항 반영
- **확정:** 기존 지출에 연결한 전액·부분 환불을 지원하고 환불 금액을 지출 집계에 반영합니다.
- **결정 필요:** 환불 집계 기준일, 복수 환불, 원거래 수정 및 환불 기록 자체의 수정·삭제 방식.

## 추후 검토

### A-09. 계좌 간 이체/카드대금 이중 집계 방지
- 결제수단별 지출 기록에 계좌 이동이나 카드대금 납부까지 포함할 경우 지출 중복 집계를 방지할 정책이 필요합니다.
- **확정:** 초기 버전은 결제수단별 사용 기록과 통계에 한정하며 카드대금 납부 및 계좌 잔액 관리는 제외합니다.

### A-10. 접근성·사용성
- **확정:** 모바일·태블릿·데스크톱에 대응하는 반응형 웹으로 구현하며 최소 지원 뷰포트 너비는 320 CSS px입니다. 320px에서도 핵심 기능을 사용할 수 있고 콘텐츠·조작 요소의 잘림이나 겹침, 페이지 전체 가로 스크롤이 없어야 합니다.
- 키보드 입력, 금액 입력 UX, 빈 상태와 오류 안내를 고려합니다.
- 별도 서버가 없는 환경에서의 오프라인 사용 범위 및 PWA 제공 여부는 추후 검토합니다.
