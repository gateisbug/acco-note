# acco-note 기능 정의서

이 문서는 [사용자 요구사항](prd.md)을 기능 단위로 정리합니다. 기능을 연결한 사용 과정은 [사용자 흐름 정의서](user-flows.md), 구체적인 검증 예시는 [핵심 사용자 시나리오](../ai/scenarios.md)를 참고합니다.

기능과 정책은 사용자 합의를 따릅니다. 남은 정책은 [상세 정책 확정본](policies.md)으로 확정했으며 PWA만 보류합니다. 기능 ID는 화면 이름이나 구현 모듈 이름과 독립적으로 유지합니다.

## 1. 사용자와 공통 기준

사용자는 자신의 수입·지출을 직접 기록하고 소비 현황과 목표를 확인하는 개인입니다. 로그인·회원가입·역할별 권한은 없으며 현재 브라우저의 데이터를 사용합니다.

| 항목 | 기준 |
| --- | --- |
| 저장 | 별도 백엔드 없이 브라우저 IndexedDB 사용 |
| 날짜 | 입력·표시·상태 판단·기간 집계 모두 Asia/Seoul 기준 |
| 금액 | 거래·환불은 KRW 정수 1~999,999,999원 |
| 거래 상태 | 오늘·과거는 확정, 미래는 예정. 예정은 실제 집계에서 제외 |
| 입력 오류 | 거래·환불의 해당 필드 아래 이유 표시, 입력 유지, 저장 차단, 기존 기록·집계 유지 |
| 화면 | 모바일·태블릿·데스크톱 대응, 최소 320 CSS px, 잘림·겹침·페이지 전체 가로 스크롤 방지 |
| 범위 제외 | 로그인, 백엔드, 실제 결제·카드 연동, 계좌 잔액, 카드대금 관리, JSON 병합 |

예산은 0~999,999,999원, 목표·저축·인출은 1~999,999,999원 정수입니다. 저장 실패·지원 브라우저·제한적 오프라인은 P-08을 적용하며 PWA는 보류합니다.

## 3. 기능별 정의

### F-01. 거래 등록

- **시작:** 사용자가 날짜별 내역을 기록하려고 한다. 카테고리·결제수단 등록은 필수가 아니다.
- **입력:** 날짜·수입/지출 유형·금액·내역명 필수. 카테고리·메모·지출 결제수단 선택. 날짜 기본값은 한국 시간 기준 오늘이다.
- **규칙:** 금액은 공통 제한을 적용하고 내역명은 최대 100자, 메모는 최대 1,000자이다. 수입·지출은 금액의 부호 대신 유형으로 구분한다. 보관 카테고리·결제수단은 신규 선택할 수 없다.
- **결과:** 오늘·과거 거래는 해당 거래일에 확정 반영한다. 미래 거래는 예정으로 저장하고 F-03에 연결한다.
- **완료:** 저장한 내역이 조회되며 확정 거래만 해당 기간 통계와 지출 예산에 반영된다. 수입은 지출 예산 사용액을 늘리지 않는다.
- **추가 확정:** 유형 변경 시 분류 해제, 수입 전환 시 결제수단 해제, 공백 이름 금지. 상세 규칙은 [정책 P-01](policies.md)을 적용한다.

### F-02. 거래 수정·삭제

- **시작:** 기존 거래를 조회하고 수정 또는 삭제를 선택한다.
- **입력:** 수정할 거래 필드 또는 삭제 확인. 등록과 같은 입력 제한을 적용한다.
- **규칙:** 날짜를 미래로 옮기면 예정으로, 오늘·과거로 옮기면 확정으로 전환한다. 기존 보관 카테고리·결제수단 연결은 유지할 수 있으나 다른 보관 항목을 새로 연결할 수 없다.
- **환불 연결:** 연결 환불이 있으면 날짜·금액·유형 변경을 막는다. 원거래 삭제 확인에는 연결 환불도 함께 삭제됨을 안내한다.
- **고정지출 연결:** 날짜 변경 후에도 원래 회차 연결을 유지한다. 생성 거래 삭제는 해당 회차를 건너뜀으로 처리하여 재생성을 막는다. 환불이 연결되어 있으면 환불 삭제 규칙도 함께 적용한다.
- **결과:** 이전 집계 반영을 제거하고 수정된 거래일·금액·상태로 갱신한다. 삭제 취소 시 거래·환불·회차·집계가 유지된다.
- **완료:** 삭제는 확인 후 적용하며 개별 거래의 실행 취소·휴지통은 제공하지 않는다. JSON 전체 복원은 F-12의 별도 기능이다.
- **추가 확정:** 환불 연결 거래의 날짜·금액·유형 변경 제한, 고정지출 생성 거래는 지출 유지. 상세 규칙은 [정책 P-01](policies.md)을 적용한다.

### F-03. 예정 거래 자동 확정

- **시작:** 예정 거래일의 한국 시간 00:00이 되거나 앱 실행 시 미처리 거래일이 지난 상태이다.
- **대상:** 일반 예정 거래와 건너뛰지 않은 고정지출 회차.
- **규칙:** 사용자 확인 없이 확정한다. 앱 미실행 중 도래한 거래는 다음 실행 시 처리하며 거래일을 처리일로 바꾸지 않는다.
- **날짜 변경:** 고정지출 회차의 날짜를 개별 수정했다면 원래 반복일 대신 변경한 거래일을 기준으로 확정한다.
- **결과:** 해당 거래일의 통계·예산에 한 번만 반영한다. 같은 거래·회차를 다시 처리해도 중복 생성·집계하지 않는다.
- **완료:** 예정·건너뜀 항목은 실제 집계에서 제외되고, 도래한 유효 거래만 확정된다.
- **추가 확정:** 복원 데이터 대체와 도래 예정 거래 확정을 원자적으로 적용. 상세 규칙은 [정책 P-07](policies.md)을 적용한다.

### F-04. 고정지출과 회차 관리

- **시작:** 사용자가 반복되는 지출을 등록하거나 특정 회차를 관리한다.
- **입력:** 반복 주기(매일·매주·매월·매년), 시작일 필수, 종료일 선택, 반복 기본 금액. 내역명 필수, 카테고리·결제수단·메모 선택이며 거래와 같은 입력 제한을 적용한다.
- **반복 규칙:** 종료일이 없으면 계속 반복한다. 해당 달에 지정일이 없으면 말일을 사용하되 원래 기준일을 유지한다. 매년 2월 29일은 평년에 2월 28일을 사용한다.
- **개별 회차:** 예정 금액과 확정 후 실제 금액을 수정할 수 있다. 변경은 해당 회차에만 적용한다. 날짜 변경 후에도 원래 회차 연결을 유지한다.
- **건너뜀:** 특정 회차를 건너뛰면 자동 확정하지 않는다. 취소하면 오늘·과거 회차는 즉시 확정하고 미래 회차는 예정으로 복원한다.
- **설정 변경:** 미확정 회차부터 적용하되 확정 거래와 개별 수정·건너뜀 회차는 유지한다.
- **중지·삭제:** 앞으로의 예정 회차를 개별 수정 여부와 관계없이 제거하고 이후 자동 생성·확정을 막는다. 이미 확정된 거래와 집계는 유지한다.
- **완료:** 회차당 실제 거래가 중복되지 않으며 개별 수정이 반복 기본 금액과 이후 회차를 바꾸지 않는다.
- **추가 확정:** 종료일 포함, 과거 시작일 미리보기, 중지 전 도래분 확정, 재개일부터 생성, 삭제 설정 복원 금지. 상세 규칙은 [정책 P-05](policies.md)을 적용한다.

### F-05. 카테고리 관리

- **시작·입력:** 기본 카테고리를 확인하거나 수입/지출 구분과 이름으로 카테고리를 추가·수정한다.
- **규칙:** 하위 분류 없이 1단계로 관리한다. 사용 중인 항목은 보관하여 기존 거래를 유지하고 신규 선택에서 제외한다.
- **결과:** 거래 입력·편집에서 사용할 분류를 제공하고 카테고리별 예산 한도와 연결한다.
- **완료:** 보관해도 과거 거래와 기존 연결은 사라지지 않는다.
- **추가 확정:** 기본 목록·이름 검증·참조 없는 항목 삭제·보관 해제 지원, 기존 반복·예산 연결 계승. 상세 규칙은 [정책 P-04](policies.md)을 적용한다.

### F-06. 결제수단 관리

- **시작·입력:** 사용자가 '현금', '생활비 카드' 등의 이름을 등록·수정한다.
- **규칙:** 지출에서 선택적으로 연결한다. 사용 중인 수단은 보관하고 기존 거래 연결을 유지하며 신규 선택만 막는다.
- **결과:** 수단별 사용 내역과 통계 조회의 기준을 제공한다. 실제 결제를 실행하거나 카드·계좌를 연결하지 않는다.
- **완료:** 보관된 수단의 기존 거래를 수정해도 해당 연결을 유지할 수 있다.
- **추가 확정:** 6개 유형·이름 검증·삭제·보관 해제, 순사용액·횟수·환불 전 비중 제공. 상세 규칙은 [정책 P-04](policies.md)을 적용한다.

### F-07. 환불 기록·수정·삭제

- **시작:** 확정 지출의 상세에서 환불을 기록한다. 수입·예정 거래·건너뛴 회차에는 등록하지 않는다.
- **입력:** 원거래 자동 연결, 환불일·금액 필수, 메모 선택. 원거래 연결은 수정할 수 없다. 환불일 기본값은 오늘이며 원거래일 이상 오늘 이하만 허용한다.
- **검증:** 금액은 공통 제한, 메모는 최대 1,000자이다. 여러 환불의 합계는 원거래 금액 이하이다. 수정 시 현재 환불을 제외한 합계로 남은 한도를 계산한다.
- **표시:** 남은 환불 가능액을 표시한다. 환불의 별도 내역명·카테고리·결제수단은 입력받지 않는다.
- **수정:** 날짜·금액·메모를 검증 후 별도 확인창 없이 저장한다. 기존 환불 반영을 제거하고 변경된 환불일·금액으로 반영한다.
- **삭제:** 원거래 유지와 차감 제거를 안내하고 확인 후 해당 환불만 삭제한다. 취소하면 기록·집계를 유지한다. 실행 취소·휴지통은 제공하지 않는다.
- **결과:** 환불일의 지출·예산에서 차감한다. 환불 삭제 시 해당 환불일의 사용액에 금액을 되돌린다. 원거래 금액·회차 상태는 유지한다.
- **완료:** 마지막 환불을 삭제하면 원거래의 날짜·금액·유형 수정 제한이 해제된다. 거래 종류에 따른 다른 수정 규칙은 계속 적용한다.
- **추가 확정:** 원거래의 현재 분류·결제수단으로 연결 환불 재분류, 환불일·전체 사용액 유지. 상세 규칙은 [정책 P-04](policies.md)을 적용한다.

### F-08. 월 예산 관리

- **시작·입력:** 대상 월의 전체 지출 예산을 설정하고 선택적으로 카테고리별 한도를 설정한다.
- **규칙:** 실제 지출을 사용액에 포함하고 해당 월 환불을 차감한다. 미확정 거래는 제외하며 고정지출 예정액은 별도로 표시한다. 카테고리 없는 지출도 전체 사용액에는 포함한다.
- **결과:** 사용액·잔여액·초과액을 확인한다. 거래·환불 수정·삭제·자동 확정 결과가 반영된다.
- **완료:** 예산 1,000,000원, 확정 지출 600,000원, 환불 없음이면 사용액 600,000원·잔여액 400,000원이다. 예정액 50,000원은 여기에 합산하지 않는다.
- **추가 확정:** 한도 합계 초과 경고 후 허용, 음수 잔여액·사용액 표시, 월별 수정·삭제·복사 지원, 자동 이월 제외. 상세 규칙은 [정책 P-02](policies.md)을 적용한다.

### F-09. 저축 목표와 기록

- **시작·입력:** 목표명·목표금액·시작일·목표일로 목표를 만들고 해당 목표에 저축 실적을 직접 기록한다. 여러 목표를 만들 수 있다.
- **규칙:** 목표별 누적 저축액과 목표금액을 비교한다. 저축 기록으로 수입·지출을 자동 생성하거나 지출 예산 사용액을 바꾸지 않는다.
- **결과:** 목표금액 1,000,000원에 200,000원을 기록하면 누적액 200,000원, 진행률 20%이다.
- **완료:** 각 목표의 진행률은 해당 목표의 기록으로 계산된다.
- **추가 확정:** 저축·인출 수정·삭제와 날짜별 잔액 검증, 목표 변경·보관·복원, 달성·기한 경과 계산. 직접 이동·자동 배분 제외. 상세 규칙은 [정책 P-03](policies.md)을 적용한다.

### F-10. 내역 조회·시각화

- **시작·입력:** 사용자가 일·주·월 단위로 기간을 선택하고 내역과 현황을 확인한다.
- **규칙:** 확정 거래와 환불을 각 기록의 날짜 기준으로 집계하며 예정 항목을 실제 집계에 포함하지 않는다.
- **결과:** 거래 상세를 확인하고 수정·삭제·환불 기능으로 이어진다. 결제수단별 사용 현황을 확인할 수 있어야 한다.
- **완료:** 같은 기간의 내역과 집계에 같은 확정 기준을 사용하며 변경 결과가 일치한다.
- **추가 확정:** 이번 달 목록·달력 전환·월요일 주간·검색·필터·기간 비교·통계 제공. 상세 규칙은 [정책 P-06](policies.md)을 적용한다.

### F-11. JSON 내보내기

- **시작:** 사용자가 데이터 내보내기를 실행한다.
- **입력·결과:** 현재 브라우저의 가계부 데이터를 JSON 파일로 내보낸다. 이 파일은 F-12의 복원 입력이다.
- **완료:** 내보낸 파일로 복원을 진행할 수 있어야 한다. 백업 범위와 검증 항목은 P-07·P-10을 적용한다.
- **추가 확정:** 거래부터 목표·회차 상태·보기 설정까지 전체 백업, 버전 1만 지원. 주기적 자동 백업·리마인더 제외. 상세 규칙은 [정책 P-07](policies.md)을 적용한다.

### F-12. JSON 가져오기

- **시작·입력:** 사용자가 복원할 JSON 파일을 선택한다.
- **규칙:** 구조·값을 검증하고 대체할 내용을 보여준 후 확인받는다. 확인 전에는 기존 데이터를 바꾸지 않는다.
- **결과:** 확인하면 기존 데이터를 전체 대체한다. 병합하지 않는다. 실패·취소 시 기존 데이터를 유지하며 일부만 대체된 상태로 남기지 않는다.
- **완료:** 성공한 복원 데이터가 조회되며, 실패·취소한 경우 기존 기록과 연결 관계가 유지된다.
- **추가 확정:** 참조·중복·값 검증과 미리보기, 복원 직전 사본 보존 후 전체 대체·자동 확정 원자적 적용. 상세 규칙은 [정책 P-07](policies.md)을 적용한다.
