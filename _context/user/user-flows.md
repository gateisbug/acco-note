# acco-note 사용자 흐름 정의서

사용자가 기능을 어떤 순서로 사용하고, 한 기능의 결과가 다른 기능에 어떻게 이어지는지 정의합니다. [기능 정의서](functions.md)의 ID를 참조하며 [사용자 요구사항](prd.md)을 정책 기준으로 삼습니다.

아래 흐름은 논리적인 작업 순서입니다. 기본 진입은 이번 달 목록이며 탐색·배치는 [상세 정책 P-06](policies.md)을 따릅니다. 추가 동작은 P-09, 완료 조건은 P-10을 함께 적용합니다.

## 1. 전체 사용 흐름

| 사용자 목적 | 연결되는 작업 | 최종 확인 |
| --- | --- | --- |
| 첫 내역 기록 | 앱 열기 → 선택적으로 분류·결제수단 준비 → 거래 등록 | 날짜별 내역·실제 집계 |
| 소비 관리 | 내역 조회 → 거래 정정 또는 환불 기록 → 현황 확인 | 변경된 기간 통계·월 예산 |
| 반복 지출 관리 | 반복 등록 → 회차 확인·조정 → 날짜 도래·자동 확정 | 실제 거래·월 예산 |
| 저축 관리 | 목표 생성 → 해당 목표에 실적 기록 | 목표별 누적액·진행률 |
| 데이터 보관·복원 | 내보내기 → 파일 보관 → 가져오기·검증·확인 | 복원된 데이터 조회 |

저축 실적은 가계부 거래와 독립적으로 기록합니다. 거래·환불은 지출 예산과 연결되지만 저축 실적은 지출 예산을 바꾸지 않습니다.

## 2. U-01 — 처음 사용하고 거래 기록하기

**목적:** 로그인 없이 첫 수입·지출을 기록한다.

**진입 조건:** 사용자가 현재 브라우저에서 앱을 연다. 기존 데이터가 없어도 시작할 수 있다.

1. 기본 카테고리를 확인한다. 필요한 경우 카테고리를 추가하고(F-05) '생활비 카드' 같은 결제수단을 등록한다(F-06).
2. 거래 등록을 시작한다(F-01). 분류·결제수단 준비를 생략한 경우에도 등록할 수 있다.
3. 기본값인 오늘 날짜를 확인하고 유형·금액·내역명을 입력한다. 분류·메모·지출 결제수단은 필요할 때만 선택한다.
4. 저장한다. 입력 오류가 있으면 해당 필드의 안내를 보고 입력을 수정한다. 입력은 사라지지 않는다.
5. 저장된 내역을 조회한다(F-10). 오늘·과거 거래는 해당 거래일의 실제 집계에 반영되고 미래 거래는 예정으로 이어진다(F-03).
6. 지출이며 해당 월 예산을 설정했다면 사용액 변화를 확인한다(F-08).

**완료:** 거래가 저장·조회되고 날짜에 맞는 상태와 집계가 일치한다.

**추가 확정:** [상세 정책 P-04·P-06·P-08](policies.md)과 P-09의 후속 흐름을 적용한다.

## 3. U-02 — 예정 거래가 실제 거래가 되기

**목적:** 미래에 발생할 수입·지출을 기록하고 날짜가 되면 실제 현황에 반영한다.

1. 미래 날짜의 일반 거래를 등록하거나(F-01) 고정지출 예정 회차를 확인한다(F-04).
2. 조회에서 예정 내역을 확인한다(F-10). 실제 수입·지출 및 예산 사용액에는 포함되지 않는다.
3. 거래일의 한국 시간 00:00부터 자동 확정 대상이 된다(F-03). 앱이 실행되지 않았다면 다음 실행에서 처리한다.
4. 사용자 확인 없이 확정하고 원래 거래일의 통계·예산에 반영한다(F-08, F-10).

**분기:** 거래일을 바꾸면 변경일을 기준으로 판단한다. 고정지출의 원래 회차 연결은 유지한다. 건너뛴 회차와 삭제한 일반 예정 거래는 자동 확정하지 않는다.

**완료:** 앱 재실행이나 반복 처리에도 거래와 집계가 한 번만 반영된다.

## 4. U-03 — 기록을 찾아 정정하거나 삭제하기

**목적:** 잘못 입력한 내역을 고치고 현황을 다시 확인한다.

1. 일·주·월 내역에서 거래를 확인하고 상세로 들어간다(F-10).
2. 수정할 필드를 입력하고 저장한다(F-02). 날짜가 달라지면 이전 기간 반영을 제거하고 변경된 날짜·상태로 집계한다.
3. 환불 때문에 날짜·금액·유형 수정이 제한되면 연결 환불을 확인한다(F-07). 환불을 모두 삭제한 후에만 해당 제한이 해제된다.
4. 거래 삭제를 선택했다면 확인창의 삭제 범위를 확인한다. 일반 거래는 해당 거래, 환불 연결 거래는 원거래와 연결 환불을 함께 삭제한다.
5. 고정지출 생성 거래 삭제 시 해당 회차는 건너뜀이 되며 이후 회차는 유지된다(F-04).
6. 변경된 내역과 해당 기간 통계·예산을 확인한다(F-10, F-08).

**취소·오류:** 삭제 취소 또는 입력 검증 실패 시 기존 기록과 집계는 유지한다. 삭제 확인 후 개별 거래 복구는 제공하지 않는다.

**완료:** 원거래·환불·회차의 연결 규칙에 맞게 변경되고 중복 집계나 자동 재생성이 없다.

## 5. U-04 — 고정지출 설정과 개별 회차 관리하기

**목적:** 반복 지출을 등록하고 실제 청구 차이나 미발생 회차를 관리한다.

1. 고정지출의 반복 주기·시작일·기본 금액을 설정하고 필요한 경우 종료일을 지정한다(F-04).
2. 해당 날짜의 예정 회차를 확인한다. 예를 들어 기본 금액이 50,000원인 통신비의 이번 회차만 48,000원으로 수정한다.
3. 날짜가 되면 해당 회차를 자동 확정한다(F-03). 실제 거래와 예산에는 48,000원만 반영한다.
4. 실제 금액이 다르면 생성 거래를 수정한다(F-02). 기본 금액과 다음 회차는 50,000원을 유지한다.
5. 이번 회차가 발생하지 않으면 예정 단계에서 건너뛰거나 생성 거래를 삭제하여 건너뜀으로 바꾼다.
6. 건너뜀을 취소하면 오늘·과거 회차는 즉시 확정하고 미래 회차는 예정으로 복원한다.

**반복 설정 변경:** 미확정 회차에 적용하되 개별 수정·건너뜀 회차와 확정 거래는 유지한다.

**반복 중지·삭제:** 앞으로의 예정 회차를 개별 수정 여부와 관계없이 제거한다. 이미 확정된 거래·집계는 유지하며 이후 자동 생성·확정을 막는다.

**완료:** 한 회차의 변경과 반복 전체 변경이 정해진 적용 범위대로 동작한다.

**추가 확정:** [상세 정책 P-05](policies.md)과 P-09의 후속 흐름을 적용한다.

## 6. U-05 — 환불을 기록하고 정정하기

**목적:** 구매를 지우지 않고 실제 환불을 기록한다.

1. 확정 지출의 상세에서 환불 등록을 시작한다(F-10 → F-07).
2. 남은 환불 가능액을 확인하고 환불일·금액, 필요하면 메모를 입력한다. 원거래는 자동 연결된다.
3. 저장하면 원거래 금액은 유지되고 환불일의 지출·예산에서 차감된다(F-08, F-10).
4. 추가 환불이 있으면 같은 원거래에서 다시 기록한다. 누적액이 원거래 금액을 넘으면 저장을 막는다.
5. 환불일·금액이 잘못되면 환불 자체를 수정한다. 이전 환불 반영을 제거하고 변경 값으로 반영한다.
6. 잘못 만든 환불은 삭제 확인 후 해당 환불만 제거한다. 해당 날짜에 차감했던 금액을 되돌리며 원거래와 회차는 유지한다.

**연결 예시:** 10월 구매 100,000원에 11월 환불 30,000원을 등록하면 10월 지출은 그대로이고 11월 사용액만 30,000원 감소한다. 두 달을 포함한 순지출은 70,000원이다.

**완료:** 환불의 원거래를 식별할 수 있고 각 환불이 자신의 날짜에 한 번 반영된다. 미래 환불·예정 거래 환불·한도 초과 환불은 저장되지 않는다.

## 7. U-06 — 예산과 소비 현황 확인하기

**목적:** 월 지출을 계획한 한도와 비교한다.

1. 대상 월의 전체 예산을 설정한다(F-08). 필요하면 카테고리별 한도를 설정한다.
2. 거래 입력·자동 확정·환불 기록을 통해 사용액이 갱신된다(F-01, F-03, F-07).
3. 월 사용액·잔여액·초과액과 고정지출 예정액을 확인한다. 예정액은 실제 사용액에 더하지 않는다.
4. 내역을 확인할 필요가 있으면 해당 기간 조회 기능을 사용한다(F-10). 해당 월·카테고리 조건을 유지한 내역 조회로 이동한다.
5. 잘못된 기록을 정정한 뒤 예산 사용액을 다시 확인한다(F-02, F-07 → F-08).

**완료:** 확정 지출 600,000원, 환불 30,000원, 예정 고정지출 50,000원이면 해당 월 실제 사용액은 570,000원이고 예정액은 별도로 남는다.

**추가 흐름:** 다른 월 예산을 복사할 때 원본·대상 월과 보관 카테고리 제외 목록을 확인한다. 대상 설정이 있으면 덮어쓰기를 확인하고 적용한다. 카테고리 한도 합계 초과는 경고 후 저장할 수 있다. 월 예산 삭제 시 전체 예산과 해당 월 한도가 제거되며 거래는 유지된다. 자동 이월은 제공하지 않는다. 계산식과 검증은 [상세 정책 P-02](policies.md)를 따른다.

## 8. U-07 — 저축 목표와 진행률 확인하기

**목적:** 소비 집계와 별도로 목적별 저축 실적을 관리한다.

1. 목표명·목표금액·시작일·목표일로 목표를 만든다(F-09).
2. 해당 목표를 선택하여 저축한 금액을 직접 기록한다.
3. 목표별 누적액과 진행률을 확인한다. 다른 목표를 만들어 각각 기록할 수 있다.
4. 가계부 내역과 예산을 조회하더라도 저축 기록 때문에 수입·지출이 추가되지 않는다.

**완료:** 1,000,000원 목표에 200,000원과 100,000원을 기록하면 누적액 300,000원·진행률 30%이고 다른 목표 실적은 그대로이다.

**추가 흐름:** 목표에서 저축·인출을 선택하고 날짜·금액·메모를 입력한다. 저장 시 해당 날짜부터 이후 모든 날짜의 누적액을 검증한다. 기존 기록 수정·삭제도 같은 검증을 거치며 음수가 되면 저장을 막는다. 목표를 보관하면 읽기만 가능하고 복원 후 편집한다. 달성·기한 경과는 자동 갱신한다. 목표 간 직접 이동·자동 배분은 제공하지 않는다. [상세 정책 P-03](policies.md)을 적용한다.

## 9. U-08 — 분류와 결제수단 정리하기

**목적:** 사용하는 항목을 정리하면서 기존 거래 이력을 보존한다.

1. 카테고리 또는 결제수단 관리에서 항목을 추가·수정한다(F-05, F-06).
2. 새 거래에서 필요한 항목을 선택한다(F-01).
3. 더 이상 사용하지 않는 기존 항목은 보관한다. 연결된 과거 거래는 유지된다.
4. 이후 새 거래에서는 보관 항목을 선택할 수 없다. 기존 거래를 수정할 때는 이미 연결된 보관 항목을 그대로 유지할 수 있다(F-02).

**완료:** 보관만으로 거래나 과거 집계가 삭제되지 않는다.

**추가 확정:** [상세 정책 P-04](policies.md)과 P-09의 후속 흐름을 적용한다.

## 10. U-09 — 백업하고 전체 복원하기

**목적:** 현재 데이터를 파일로 보관하고 필요한 시점에 백업 데이터로 돌아간다.

1. 현재 데이터를 JSON으로 내보내고 파일을 보관한다(F-11).
2. 복원이 필요하면 가져오기에서 해당 파일을 선택한다(F-12).
3. 시스템이 구조·값을 검증한다. 실패하면 오류를 확인하고 기존 데이터를 계속 사용한다.
4. 검증에 성공하면 대체할 내용을 확인한다. 기존 데이터 전체가 대체되며 병합하지 않음을 안내받는다.
5. 취소하면 기존 데이터를 유지한다. 확인하면 전체 대체를 적용한다.
6. 성공하면 복원된 데이터를 조회한다(F-10 등). 적용 실패 시 기존 데이터를 유지하고 일부만 대체된 상태를 남기지 않는다.

**완료:** 확인 전 기존 데이터는 바뀌지 않는다. 성공 시 백업 내용으로 대체되고 실패·취소 시 기존 기록과 연결 관계가 유지된다.

**추가 흐름:** 미리보기에서 현재/가져올 건수와 기간·자동 확정 대상 건수·금액을 확인한다. 확인 후 복원 직전 사본을 로컬에 보존하며 실패하면 중단한다. 데이터 전체 대체와 도래 예정 회차 확정을 함께 적용한다. 복원 직전 사본은 다운로드할 수 있다. 버전·참조·상태 검증과 실패 처리는 [상세 정책 P-07](policies.md)을 적용한다.

## 11. 기능 사이에 지켜야 할 연결 규칙

| 변경 사건 | 함께 달라지는 결과 | 유지되는 내용 |
| --- | --- | --- |
| 확정 지출 등록·금액 수정 | 거래일의 통계·예산 사용액 | 다른 거래 |
| 거래일을 미래로 이동 | 예정 전환, 이전 실제 집계 제거 | 고정지출의 원래 회차 연결 |
| 예정 거래 자동 확정 | 해당 거래일의 실제 집계 | 원래 거래일, 회차당 한 번 반영 |
| 환불 등록·수정 | 환불일의 통계·예산 차감 | 원거래 금액·회차 상태 |
| 환불만 삭제 | 환불일의 차감 취소 | 원거래·나머지 환불 |
| 환불 연결 원거래 삭제 | 원거래와 환불 각각의 날짜 집계 제거 | 다른 거래·이후 회차 |
| 고정지출 생성 거래 삭제 | 해당 회차 건너뜀, 해당 거래 집계 제거 | 반복 설정·이후 회차 |
| 반복 중지·삭제 | 앞으로의 예정 회차 제거, 이후 생성·확정 중단 | 확정 거래·집계 |
| 카테고리·결제수단 보관 | 신규 선택에서 제외 | 기존 거래 연결 |
| 저축 실적 등록 | 해당 목표 누적액·진행률 | 가계부 수입·지출·예산 사용액 |
| JSON 복원 성공 | 확정된 백업 범위의 데이터 전체 대체 | 기존 데이터 병합 없음 |

환불이 있는 고정지출 생성 거래를 삭제하는 경우에는 원거래·환불 삭제와 회차 건너뜀 규칙을 함께 적용합니다.

## 12. 화면·구현 설계로 넘길 기준

각 흐름은 320 CSS px 이상에서 핵심 동작을 수행할 수 있어야 하며 화면 크기를 바꾸어도 입력과 거래 상태를 유지합니다. 화면 설계 시 각 단계에 기능 ID를 연결하고 입력·확인·완료·취소·오류 상태를 배치합니다.

거래·환불 입력 검증과 삭제 취소, JSON 복원 실패의 동작은 위 확정 규칙을 적용합니다. 저장 실패·빈 화면·접근성은 [상세 정책 P-08](policies.md)을 적용합니다. 검색·필터·차트는 초기 범위에 포함하며 PWA는 보류합니다.
