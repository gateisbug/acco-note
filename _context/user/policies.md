# acco-note 상세 정책 확정본

2026-11-07 사용자 지시에 따라 남은 정책을 권장안으로 확정합니다. 이 문서는 [사용자 요구사항](prd.md)의 일부이며, 기능 정의와 사용자 흐름에도 동일하게 적용합니다. **PWA는 보류**합니다. 아래에서 지원하지 않기로 정한 기능은 초기 버전 범위에서 제외하며 미정으로 남기지 않습니다.

## P-01. 공통 입력과 거래 편집

- 날짜는 유효한 YYYY-MM-DD 값으로 입력하며 모든 날짜 판단은 한국 시간 기준입니다. 이름은 앞뒤 공백을 제거한 뒤 검증하고 공백만 있는 값은 거부합니다. 길이는 Unicode 코드 포인트 수로 계산합니다.
- 거래·반복 내역명과 목표명은 1~100자, 카테고리·결제수단명은 1~30자, 메모는 최대 1,000자입니다. 금액 계산과 저장은 원 단위 정수로 수행합니다.
- 일반 거래의 수입/지출 유형을 바꾸면 카테고리를 해제하고, 수입으로 바꾸면 결제수단도 해제합니다. 저장 전 바뀔 항목을 안내합니다. 환불 연결 거래는 날짜·금액·유형 변경을 막습니다. 고정지출 생성 거래는 지출 유형을 유지하며 수입으로 변경할 수 없습니다.
- 등록·수정은 검증 성공 후 저장합니다. 취소하면 기존 데이터를 유지합니다. 입력한 내용이 있는 편집 화면을 저장 없이 나갈 때 변경 폐기 확인을 제공합니다.

## P-02. 월 예산

- 전체 월 예산과 카테고리 한도는 독립적인 기준으로 사용합니다. 카테고리 한도 합계가 전체 예산을 넘어도 저장하되 경고합니다. 카테고리 한도는 전체 예산이 있는 월에 설정합니다.
- 예산·한도는 각각 0~999,999,999원의 정수입니다. 0원은 지출 허용액 0원이며 미설정과 구분합니다. 전체 예산 미설정 월에는 실제 지출만 보여주고 잔여액·초과액·진행률은 표시하지 않습니다.
- 사용액 = 해당 월 확정 지출 − 해당 월 환불입니다. 사용액은 음수도 그대로 표시합니다. 잔여액 = 예산 − 사용액이며 초과 시 음수를 표시합니다. 초과액 = max(사용액 − 예산, 0)입니다.
- 양수 예산의 사용률은 사용액/예산×100으로 표시하고 막대만 0~100%로 제한합니다. 음수·100% 초과 사용률도 숫자로 표시합니다. 0원 예산은 사용률을 '—'로 표시하며 금액과 초과 여부로 안내합니다. 비율은 소수 첫째 자리까지 표시합니다.
- 과거·현재·미래 월 예산을 수정할 수 있습니다. 월별 설정만 변경하며 실제 거래는 바꾸지 않습니다. 예산 삭제는 확인 후 해당 월 전체 예산과 카테고리 한도를 함께 제거합니다.
- 다른 월의 전체 예산과 활성 카테고리 한도를 선택한 월로 복사할 수 있습니다. 대상 설정이 있으면 덮어쓸 내용을 확인받습니다. 보관 카테고리 한도는 제외하고 제외 목록을 안내합니다. 잔여 예산 자동 이월은 지원하지 않습니다.

## P-03. 저축 목표와 기록

- 목표는 이름·목표금액·시작일·목표일 필수, 목표금액은 1~999,999,999원 정수입니다. 목표일은 시작일 이상이어야 하며 과거 기한의 목표도 등록할 수 있습니다. 미래 시작일도 허용합니다.
- 저축 기록은 목표·날짜·유형(저축/인출)·금액 필수, 메모 선택입니다. 날짜 기본값은 오늘이며 목표 시작일 이상 오늘 이하만 허용합니다. 금액은 1~999,999,999원 정수입니다. 미래 시작 목표에는 시작일 전 기록할 수 없습니다.
- 누적액은 저축 합계에서 인출 합계를 뺀 값입니다. 날짜 오름차순으로 같은 날짜의 저축을 먼저, 인출을 나중에 합산하고 매 날짜 말 누적액이 음수가 되는 저장을 막습니다. 과거 기록 수정·삭제도 이후 날짜까지 검증합니다.
- 기록 날짜·유형·금액·메모를 수정할 수 있으며 삭제는 확인 후 적용합니다. 취소·검증 실패 시 유지합니다. 기록의 연결 목표는 변경할 수 없습니다. 목표 사이 자동 배분·직접 이동은 지원하지 않으며 사용자가 각 목표에 저축·인출을 별도로 기록합니다.
- 목표명·금액·기간을 수정할 수 있습니다. 시작일을 기존 기록보다 뒤로 옮길 수 없고 목표일은 시작일 이상이어야 합니다. 목표일 이후에도 기록할 수 있으며 기한 초과는 안내 상태입니다.
- 진행률은 누적액/목표금액×100으로 소수 첫째 자리까지 표시합니다. 초과 달성을 허용하며 숫자는 100%를 넘어도 표시하고 막대만 100%로 제한합니다.
- 누적액이 목표금액 이상이면 '달성', 미달이고 오늘이 목표일보다 늦으면 '기한 경과', 그 외에는 '진행 중'입니다. 금액·기록 변경 시 다시 계산하며 달성 후에도 기록할 수 있습니다.
- 목표는 사용자가 보관·복원할 수 있습니다. 보관 중에는 읽기만 허용합니다. 기록 없는 목표만 확인 후 삭제할 수 있고 기록 있는 목표는 보관합니다. 모든 저축 동작은 가계부 통계·예산과 독립적입니다.

## P-04. 카테고리·결제수단과 환불 귀속

- 기본 지출 카테고리는 식비, 카페·간식, 교통, 주거·통신, 생활·쇼핑, 건강·의료, 교육, 문화·여가, 경조·선물, 기타 지출입니다. 기본 수입은 급여, 부수입, 이자·배당, 용돈, 기타 수입입니다.
- 카테고리는 같은 수입/지출 유형 안에서, 결제수단은 전체 목록에서 이름 중복을 막습니다. 앞뒤 공백 제거와 영문 대소문자 무시 기준이며 보관 항목도 중복 검사에 포함합니다. 사용 중인 카테고리의 수입/지출 유형은 변경할 수 없습니다.
- 결제수단은 이름과 함께 신용카드·체크카드·현금·계좌이체·간편결제·기타 중 하나의 필수 유형을 가집니다. 유형 기본값은 기타이며 수정할 수 있습니다. 초기 결제수단은 비어 있습니다.
- 거래·반복 설정·회차·예산 등 참조가 전혀 없는 항목만 확인 후 삭제할 수 있습니다. 참조가 있으면 보관합니다. 보관 해제를 지원합니다. 기본 카테고리도 같은 규칙을 적용합니다.
- 보관해도 기존 거래·예산 한도·반복 설정의 연결을 유지합니다. 기존 반복 설정에서 자동 생성되는 회차는 해당 연결을 계승할 수 있습니다. 새 반복 설정·새 한도·새 거래에서 보관 항목을 선택하는 것은 금지합니다.
- 환불의 분류·결제수단은 원거래의 현재 연결을 따릅니다. 원거래의 연결을 바꾸면 모든 연결 환불의 분류별 통계도 갱신하지만 환불일과 전체 지출·예산 사용액은 바꾸지 않습니다. 삭제된 연결 대신 미분류·미선택을 사용할 수 있습니다.
- 결제수단 사용액은 기간 내 확정 지출에서 같은 기간 환불을 뺀 값이고 사용 횟수는 확정 지출 건수입니다. 환불은 횟수에서 차감하지 않습니다. 예정액은 별도 표시하고 건너뜀은 제외합니다. 결제수단 미선택도 별도 그룹으로 표시합니다.
- 결제수단·카테고리 소비 비중은 환불 전 확정 지출액을 분모·분자로 사용하고 '환불 전 지출 비중'으로 명시합니다. 순사용액·환불액은 별도 표시합니다. 분모가 0이면 비중은 '—'로 표시합니다. 음수 순사용액에 원형 비중을 적용하지 않습니다.

## P-05. 고정지출 세부 규칙

- 반복 입력은 내역명·기본 금액·주기·시작일 필수, 종료일·지출 카테고리·결제수단·메모 선택입니다. 금액·문자 제한은 거래와 같습니다. 종료일은 시작일 이상이며 해당 날짜 회차까지 포함합니다.
- 매주는 시작일 요일, 매월은 시작일 일자, 매년은 시작일 월·일을 기준으로 합니다. 종료일은 반복 기준으로 계산한 회차일에 적용합니다. 개별 거래일을 바꾸어도 원래 회차 식별자와 종료 대상 여부는 유지합니다.
- 과거 시작일을 허용합니다. 저장 전 시작일부터 오늘까지 생성할 회차 수와 총 예정 금액을 보여주고 확인받습니다. 확인 시 건너뜀 없이 해당 기간 회차를 원래 날짜에 한 번씩 확정합니다. 취소하면 생성하지 않습니다.
- 중지·삭제 전 오늘까지 도래한 미처리 회차를 먼저 자동 확정하고 그 결과를 안내합니다. 이후 앞으로의 예정 회차를 제거하고 이미 확정된 거래를 유지합니다.
- 중지한 반복은 오늘 이상의 재개일을 지정해 재개할 수 있습니다. 원래 반복 기준일을 유지하며 재개일부터의 회차만 생성합니다. 중지 기간을 소급 생성하지 않습니다. 종료일이 지났으면 먼저 종료일을 연장·해제해야 합니다.
- 삭제한 반복 설정은 복원·재개하지 않습니다. 원래 회차 연결을 보존할 최소 식별 정보와 삭제 상태는 남겨 확정 거래가 고아 데이터가 되지 않게 합니다. 삭제 설정의 건너뜀 취소는 막습니다.
- 중지 중인 설정의 건너뜀 취소는 중지 이전 회차에만 허용합니다. 미래 회차는 재개 후 활성 범위 안에 있을 때 취소할 수 있습니다. 중지 기간의 제거 회차는 생성하지 않습니다. 건너뜀 취소로 과거 거래가 재확정되어도 삭제했던 환불은 복원하지 않습니다.
- 반복 설정 변경은 저장 시점 이후 미확정 회차에 적용합니다. 개별 수정·건너뜀 회차는 날짜를 포함한 기존 내용과 원래 식별자를 유지합니다. 같은 설정·원래 회차일 조합은 하나만 존재해야 합니다.
- 적용 경계는 변경 직전 도래 회차 처리를 완료한 뒤 한국 시간 내일부터의 원래 회차일입니다. 새 기준 시작일로 과거를 소급 생성하지 않으며 변경 대상과 적용일을 미리보기에 표시합니다. 미래 재개일을 지정한 설정은 그 날짜 전까지 '재개 예정'으로 표시합니다.

## P-06. 조회·검색·통계와 화면 구성

- 기본 진입 화면은 이번 달 내역 목록입니다. 월 요약과 날짜별 목록을 함께 보여주고 달력 보기로 전환할 수 있습니다. 별도 대시보드는 초기 버전에서 만들지 않습니다.
- 일 조회는 한국 시간 00:00부터 다음 날 00:00 전까지, 주는 월요일부터 일요일, 월은 매월 1일부터 말일까지입니다. 날짜 범위 필터의 시작·종료일은 모두 포함합니다.
- 기간, 수입/지출, 카테고리, 결제수단, 상태(확정/예정/건너뜀), 내역명·메모 키워드 검색을 지원합니다. 조건 간 AND, 같은 필터 내 복수 선택은 OR입니다. 키워드는 앞뒤 공백을 제거하고 대소문자를 무시하는 부분 일치입니다.
- 환불은 지출 조회에 포함하고 환불일로 필터링합니다. 분류·수단·내역명은 원거래를 따르며 키워드는 원거래 내역명과 환불 메모를 검색합니다. 목록에서 원거래 상세로 이동할 수 있습니다.
- 확정·일반 예정·고정지출 예정·건너뜀·환불을 텍스트와 아이콘으로 구분합니다. 날짜별 목록에 표시하며 달력에는 일별 확정 합계와 예정 표시를 제공합니다. 고정지출 상세에는 회차 상태와 개별 수정 표시를 제공합니다.
- 기본 목록은 확정·예정·환불을 표시하고 건너뜀은 상태 필터 또는 고정지출 상세에서 확인합니다. 선택된 전체 기간의 확정 요약과 '필터 결과 합계'를 구분하며 예정액은 별도로 표시합니다. 미래 회차는 선택한 조회 기간에 필요한 범위를 계산하되 중복 저장하지 않습니다.
- 통계는 총수입, 순지출, 차액(수입−순지출), 환불액, 결제수단별 사용액·횟수, 카테고리별 순지출·환불 전 비중을 제공합니다. 일별 수입·순지출 막대와 월별 최근 12개월 추이를 제공합니다. 차트와 같은 값의 표도 제공합니다.
- 일·주·월 비교는 직전 동일 달력 단위와 비교합니다. 진행 중인 기간은 직전 기간의 동일 경과 일수까지만 비교하고 이전 월 일수가 짧으면 말일에서 끝냅니다. 비교 범위를 표시합니다. 사용자 지정 기간은 바로 앞의 같은 일수와 비교합니다. 기준값이 0 이하이면 증감률 대신 금액 차이만 표시합니다.
- 내역, 예산, 저축, 관리의 네 탐색 영역을 사용합니다. 관리는 고정지출·카테고리·결제수단·백업을 포함합니다. 320~767px은 하단 탐색과 단일 열, 768~1199px은 왼쪽 탐색과 단일 본문, 1200px 이상은 왼쪽 탐색과 목록/상세 두 열을 사용합니다.
- 좁은 화면의 상세·입력은 별도 화면으로, 넓은 화면은 상세 패널로 표시합니다. 예산·저축 카드는 모바일 한 열, 태블릿 두 열, 데스크톱 세 열로 배치하며 입력 폼은 단일 열입니다. 필터는 모바일에서 펼침 영역, 넓은 화면에서 상단 영역으로 제공합니다. 백업 미리보기 표는 모바일에서 항목별 카드로 바꿉니다.

## P-07. JSON 백업·복원

- 전체 내보내기는 거래, 환불, 카테고리, 결제수단, 반복 설정(중지·삭제 상태 포함), 회차 식별·개별 수정·건너뜀 및 중지 구간, 월 예산·카테고리 한도, 저축 목표·기록·보관 상태, 보기 설정을 포함합니다. 집계 캐시·미저장 입력·복원 직전 백업 사본은 포함하지 않습니다.
- 파일은 schemaVersion=1, exportedAt(UTC ISO 날짜시간), timezone=Asia/Seoul, currency=KRW와 데이터를 포함합니다. 파일명은 acco-note-backup-YYYYMMDD-HHmmss.json이며 파일명 시각은 한국 시간입니다. 초기 버전은 정확히 버전 1만 허용하며 누락·다른 버전은 거부합니다. 자동 형식 변환은 지원하지 않습니다.
- 필수 필드·자료형·날짜·정수 범위·열거값·이름 중복과 모든 참조를 검증합니다. ID 중복, 없는 원거래·목표·분류·수단·반복 참조, 회차 중복, 수입에 연결한 환불, 원거래보다 앞선·미래 환불, 누적 초과 환불, 음수가 되는 저축 잔액, 잘못된 예산·반복 기간을 거부합니다. 동일 내용이어도 서로 다른 유효 ID의 일반 거래는 허용합니다.
- 예정 거래일이 지난 것은 오류가 아니며 복원 중 자동 확정 대상으로 분류합니다. 미래 날짜의 확정 거래나 건너뜀 회차에 활성 거래가 있는 등 상태 모순은 거부합니다. 삭제 반복의 과거 거래 참조는 보존된 식별 정보가 있을 때 유효합니다.
- 미리보기에는 파일 생성일·버전, 현재/가져올 항목별 건수, 거래 기간, 통화·시간대, 자동 확정 대상 건수·금액, 전체 대체 경고를 표시합니다. 검증 오류는 항목 종류·ID·이유를 표시하고 적용을 막습니다.
- 최종 확인 시 현재 데이터를 로컬에 '복원 직전 백업' 한 개로 먼저 보존합니다. 보존 실패 시 가져오기를 중단합니다. 기존 데이터는 다음 성공적인 복원까지 이 사본으로 다운로드할 수 있습니다. 사본은 같은 브라우저에 있으므로 외부 파일 백업을 대신하지 않음을 안내합니다.
- 가져온 데이터 대체와 지난 예정 거래 자동 확정을 같은 원자적 적용 안에서 처리합니다. 복원 시 반복 규칙으로 오늘까지 필요한 누락 회차도 계산하되 건너뜀·중지·삭제·개별 변경을 존중합니다. 확인까지 날짜가 바뀌면 대상과 미리보기를 다시 계산해 재확인합니다. 실패 시 기존 데이터 전체를 유지합니다.
- 복원 직전 백업 외의 주기적 자동 백업과 백업 리마인더는 초기 버전에서 지원하지 않습니다. 사용자가 직접 파일로 내보냅니다.

## P-08. 사용 환경·오류·오프라인

- 지원 대상은 릴리스 시점 Chrome·Edge·Firefox 데스크톱 및 Safari(macOS/iOS), Chrome(Android)의 최신 안정 버전과 직전 주요 버전입니다. 인앱 브라우저·구형 브라우저·비공개 모드는 지원 보장 대상에서 제외합니다. 고정 버전 번호는 출시 테스트에서 기록합니다.
- 최초 사용 때 데이터가 현재 브라우저에만 저장되고 기기 동기화가 없으며 브라우저 데이터 삭제·기기 변경 전 JSON 내보내기가 필요함을 안내합니다. 기본 카테고리는 새 저장소에 한 번만 생성하며 복원 데이터에 다시 합치지 않습니다.
- 저장소 사용 가능 여부를 확인합니다. 쓰기 실패 시 성공으로 표시하지 않고 기존 데이터와 집계를 유지합니다. 저장 실패 이유와 재시도·백업 방법을 안내하며 열린 화면의 입력을 유지합니다. 탭 종료·새로고침 후 미저장 입력 복구는 보장하지 않고 이탈 시 안내합니다.
- 여러 탭의 변경은 저장 시 충돌을 검사합니다. 편집 중 대상이 다른 탭에서 바뀌면 덮어쓰지 않고 입력을 유지한 채 최신 데이터 재확인을 요구합니다. 자동 확정·복원도 중복 또는 부분 저장이 없도록 처리합니다.
- 키보드만으로 탐색·입력·확인·취소가 가능해야 합니다. 입력 레이블·오류 설명을 연결하고 포커스를 표시합니다. 대화상자는 포커스를 내부에 유지하고 닫으면 이전 위치로 복귀합니다. 상태는 색상만으로 구분하지 않으며 터치 조작 영역은 최소 44×44 CSS px입니다.
- 거래·목표·예산이 없으면 해당 내용을 설명하고 추가 동작을 제공합니다. 검색 결과가 없으면 조건 초기화를 제공합니다. 차트 데이터가 없으면 0과 '데이터 없음'을 구분하며 오류를 빈 데이터처럼 표시하지 않습니다.
- 일반 웹으로 제공합니다. 페이지가 이미 로드된 상태에서는 네트워크 없이 로컬 입력·조회·집계와 파일 백업·복원을 사용할 수 있도록 합니다. 오프라인 첫 접속·새로고침·닫은 앱 재실행은 보장하지 않습니다.
- **PWA 보류:** 서비스 워커, 설치 유도, 앱 셸 오프라인 캐시, 백그라운드 동기화·알림은 구현하지 않습니다. PWA 재개는 별도 사용자 결정 후 진행합니다.

## P-09. 사용자 흐름에 추가되는 동작

- 예산: 월 선택 → 설정/수정 → 한도 합계 경고 확인 → 저장 → 실제/예정 분리 조회. 복사 시 원본·대상 월과 제외될 보관 한도를 확인하고 대상 덮어쓰기를 확인합니다.
- 저축: 목표 선택 → 저축 또는 인출 → 날짜별 잔액 검증 → 저장 → 진행 상태 갱신. 기록 수정·삭제도 같은 검증을 거칩니다. 보관 목표는 복원한 뒤 편집합니다.
- 고정지출: 과거 시작일 등록은 생성 미리보기와 확인을 거칩니다. 중지·삭제는 도래 회차 처리 후 적용하고 재개는 재개일 이후만 생성합니다.
- 분류: 삭제 시 참조가 있으면 삭제 대신 보관으로 안내합니다. 보관 해제 후 신규 선택이 다시 가능해집니다. 원거래의 분류 수정은 연결 환불의 분류별 집계도 함께 갱신합니다.
- 조회: 이번 달 목록 → 기간/검색/필터 변경 → 결과·필터 합계 확인 → 거래 또는 환불 상세 → 수정 후 동일 조회 조건으로 복귀합니다.
- 복원: 파일 검증 → 미리보기 → 전체 대체 확인 → 복원 직전 백업 보존 → 전체 적용과 도래 회차 확정 → 결과 조회 순서입니다.

| 같은 회차 중복 또는 없는 원거래를 참조한 JSON | 적용 전 거부, 현재 데이터 유지 |
| 복원 직전 백업 저장 실패 또는 전체 적용 실패 | 가져오기 중단, 현재 데이터·연결 관계 유지 |
| 도래 예정 거래가 있는 정상 JSON 복원 | 미리보기 건수와 실제 확정 건수 일치, 재실행 시 중복 없음 |
