# acco-note 사용자 요구사항 (초안)

> 사용자가 직접 제시한 요구사항을 기록합니다. 구체적인 구현 및 미확정 정책은 추후 논의합니다.

## 1. 서비스 및 데이터 관리

- 로그인 및 회원가입 기능은 제공하지 않습니다.
- 별도의 백엔드 서버 없이 동작하는 웹 기반 가계부로 구성합니다.
- 모든 날짜·시간의 입력·표시·판단과 기간별 집계는 기기의 현지 시간대와 관계없이 한국 시간(Asia/Seoul, KST)을 기준으로 합니다.
- 가계부 데이터는 브라우저의 IndexedDB(IDB)에 저장하고 관리합니다.
- 가계부 데이터를 JSON 형식으로 내보내기(Export) 및 가져오기(Import) 할 수 있어야 합니다.
- JSON 가져오기는 기존 데이터를 전체 대체합니다. 병합은 지원하지 않습니다.
- 가져오기 전에 JSON 데이터 구조와 값의 유효성을 검증하고, 대체할 내용을 사용자에게 보여준 뒤 확인을 받아 적용합니다.
- 검증 또는 적용에 실패하면 기존 데이터를 유지하고 오류를 안내합니다. 일부 데이터만 대체된 상태로 남지 않아야 합니다.

## 2. 가계부 작성

- 사용자가 날짜별 가계부 내역을 직접 작성할 수 있어야 합니다.
- 새 거래의 날짜 기본값은 한국 시간 기준 오늘입니다.
- 과거 날짜의 수입·지출 신규 입력을 허용합니다. 오늘 또는 과거 날짜로 등록한 거래는 즉시 확정하고, 입력한 거래일의 통계와 해당 기간의 예산 집계에 반영합니다.
- 각 가계부 내역은 **지출** 또는 **수입** 타입을 선택할 수 있어야 합니다.
- 필수 입력 항목은 날짜, 수입/지출 유형, 금액, 내역명입니다.
- 거래 등록·수정 시 필수 항목이 누락되거나 입력값이 유효하지 않으면 해당 항목 바로 아래에 오류 이유를 표시합니다. 입력한 내용은 유지하고, 오류가 해결되기 전에는 저장하지 않습니다. 저장된 기존 거래와 통계·예산 집계도 변경하지 않습니다.
- 거래 금액은 원화(KRW)만 사용하며, 거래 1건당 1원 이상 999,999,999원 이하의 정수로 입력합니다. 0원·음수·소수 및 상한을 초과하는 금액은 허용하지 않습니다.
- 거래 내역명은 최대 100자, 메모는 최대 1,000자까지 입력할 수 있습니다. 금액·글자 수 제한은 거래 등록과 수정에 동일하게 적용하며, 초과 시 해당 항목 아래에 이유를 표시하고 입력 내용을 유지한 채 저장을 막습니다.
- 수입과 지출은 유형으로 구분하며, 환불은 음수 거래 대신 원래 지출에 연결한 별도 환불 기록으로 처리합니다.
- 카테고리, 메모, 지출 결제수단은 선택 입력 항목입니다.
- 등록된 내역은 수정하거나 삭제할 수 있어야 합니다.
- 일반 거래는 삭제 확인창에서 사용자가 확인한 후 삭제하며, 관련 통계와 예산 집계에서도 즉시 제외합니다. 취소하면 거래와 집계를 유지합니다.
- 초기 버전의 거래 삭제는 삭제 전 확인만 제공하며, 삭제 후 실행 취소·휴지통·개별 거래 복구 기능은 제공하지 않습니다.
- 고정지출에서 생성된 거래의 삭제는 고정지출 관리의 회차 처리 규칙을 적용합니다. 환불이 연결된 거래는 환불·취소 처리의 삭제 규칙을 함께 적용합니다.
- 미래 날짜의 수입·지출도 입력할 수 있으며, 확정 거래가 아닌 예정 거래로 저장합니다.
- 예정 거래는 확정 전까지 실제 수입·지출 통계 및 예산 사용액에 포함하지 않습니다.
- 일반 예정 거래와 고정지출 예정 회차는 해당 날짜가 되면 사용자 확인 없이 자동 확정하여 실제 수입·지출과 예산 집계에 반영합니다. 건너뛴 고정지출 회차는 제외합니다.
- 앱이 실행되지 않아 처리하지 못한 예정 거래는 다음 실행 시 날짜가 도래한 항목을 자동 확정합니다. 거래일은 원래 예정일로 유지하며 반복 실행으로 중복 반영되지 않아야 합니다.
- 날짜 도래는 기기의 현지 시간대와 관계없이 한국 시간(Asia/Seoul)을 기준으로 판단합니다. 예정일의 한국 시간 00:00부터 자동 확정 대상이 됩니다.
- 일반 거래의 날짜를 수정하면 한국 시간 기준으로 상태도 변경합니다. 미래 날짜로 변경하면 예정으로 전환하여 실제 집계에서 제외하고, 오늘 또는 과거 날짜로 변경하면 확정하여 변경된 날짜의 집계에 반영합니다.
- 환불이 연결된 원거래의 날짜·금액은 수정할 수 없습니다. 연결된 환불 기록을 모두 삭제한 후 수정할 수 있습니다.

## 3. 결제수단 관리

- 가계부 지출 내역에 사용한 결제수단(카드 등)을 기록할 수 있어야 합니다.
- 어떤 결제수단을 얼마나 사용했는지 확인할 수 있어야 합니다.
- 초기 버전은 카드·현금 등 결제수단별 사용 기록과 통계를 지원합니다. 카드대금 납부 및 계좌 잔액 관리는 범위에서 제외합니다.
- 결제수단의 목적은 **실제 결제 처리나 카드 연동이 아닌, 사용 내역 기록 및 분석**입니다.
- 사용자가 '현금', '생활비 카드' 등 직접 이름을 붙여 결제수단을 등록하고 수정할 수 있어야 합니다.
- 기존 내역에서 사용 중인 결제수단은 보관 처리하여 기존 내역을 유지하고 신규 선택에서 제외합니다.
- 기존 거래를 수정할 때 이미 연결된 보관 결제수단을 그대로 유지할 수 있습니다. 보관된 결제수단을 새 거래에 선택하거나 기존 거래에 새로 연결할 수는 없습니다.
- 결제수단의 유형 구분과 통계 세부 항목은 추후 결정합니다.

## 4. 고정지출 관리

- 고정지출 항목을 일반 가계부 내역과 별도로 관리할 수 있어야 합니다.
- 반복 주기는 매일·매주·매월·매년을 지원합니다. 시작일은 필수이며 종료일은 선택입니다. 종료일을 지정하지 않으면 계속 반복합니다.
- 매월·매년 반복에서 지정한 날짜가 해당 달에 없으면 그달의 마지막 날에 회차를 적용합니다. 이 보정으로 원래 반복 기준일을 변경하지 않습니다. 예를 들어 매월 31일은 2월 말일에 적용한 뒤 3월에는 다시 31일에 적용하며, 매년 2월 29일은 평년에는 2월 28일, 윤년에는 2월 29일에 적용합니다.
- 고정지출 항목은 예정일 전까지 해당 날짜의 가계부 화면에 예정으로 표시하며, 예정일이 되면 자동으로 실제 지출로 등록합니다. 자동 확정 전에는 실제 지출로 집계하지 않습니다.
- 특정 회차의 예정 지출을 건너뛸 수 있으며, 건너뛴 회차는 실제 지출로 집계하지 않습니다.
- 자동 확정 전에 해당 회차의 예정 금액을 변경할 수 있으며, 확정 후에는 거래 수정 기능으로 실제 금액을 정정할 수 있습니다.
- 자동 확정 처리를 여러 번 수행해도 같은 회차의 실제 지출이 중복 등록되지 않아야 합니다.
- 고정지출에서 자동 생성된 거래를 삭제하면 관련 통계·예산에서 제외하고 해당 회차를 '건너뜀'으로 처리하여 자동으로 다시 생성되지 않도록 합니다. 반복 설정과 이후 회차는 유지합니다.
- 고정지출에서 생성된 거래의 날짜를 변경해도 원래 회차와의 연결을 유지합니다. 실제 집계는 이전 거래일에서 제외하고 변경한 거래일의 통계·예산에 반영합니다. 원래 회차의 거래를 중복 생성하지 않으며 반복 설정과 이후 회차는 유지합니다.
- 고정지출 생성 거래도 날짜를 한국 시간 기준 미래로 변경하면 예정 상태로 전환하고 실제 통계·예산 집계에서 제외합니다. 원래 회차 연결은 유지하되, 자동 확정은 원래 예정일이 아닌 변경한 날짜의 한국 시간 00:00부터 수행합니다. 앱 미실행 시 다음 실행에서 변경한 거래일로 한 번만 반영합니다. 오늘·과거 날짜로 변경하면 즉시 확정하여 변경한 거래일의 집계에 반영합니다.
- 환불이 연결된 고정지출 거래에도 날짜·금액 수정 제한을 적용합니다.
- 반복 설정 변경은 아직 확정되지 않은 회차부터 적용합니다. 이미 확정된 거래와 사용자가 개별적으로 수정하거나 건너뜀 처리한 회차는 기존 내용과 상태를 유지하며 덮어쓰지 않습니다.
- 고정지출 반복을 중지하거나 반복 설정을 삭제하면 앞으로의 예정 회차를 제거하고 이후 회차를 자동 생성·확정하지 않습니다. 개별적으로 수정한 미래 예정 회차도 제거 대상이며, 이미 확정된 거래와 그 통계·예산 집계는 유지합니다. 이는 반복 설정 변경 시 개별 수정 회차를 유지하는 규칙과 구분합니다.
- 사용자가 회차의 '건너뜀'을 취소할 수 있습니다. 한국 시간 기준 해당 회차 날짜가 오늘 또는 과거이면 즉시 확정하여 해당 거래일의 통계·예산에 한 번만 반영하고, 미래이면 예정으로 복원하여 해당 날짜에 자동 확정합니다. 이는 일반 거래의 삭제 실행 취소와 구분되는 회차 관리 기능입니다.
- 개별 회차 금액 변경이 이후 회차의 기본 금액에 영향을 주는지는 추후 결정합니다.

## 5. 목표 설정

- 월 지출 예산과 저축 목표를 모두 설정할 수 있어야 합니다.

### 5.1. 월 지출 예산

- 월별 전체 지출 예산을 설정하고, 선택적으로 카테고리별 지출 한도를 설정할 수 있어야 합니다.
- 예산 사용액은 실제 지출을 기준으로 집계하며, 고정지출 예정액은 별도로 표시합니다.
- 사용액, 잔여액, 초과액을 표시합니다.
- 전체 예산과 카테고리별 한도의 관계, 월별 예산 이월 및 환불의 예산 반영 시점은 추후 결정합니다.

### 5.2. 저축 목표

- 목표명, 목표금액, 시작일, 목표일을 설정할 수 있어야 합니다.
- 여러 저축 목표를 등록할 수 있어야 합니다.
- 목표별로 저축한 금액을 직접 기록하고, 누적 기록 금액을 목표금액과 비교하여 진행률을 계산합니다.
- 저축 기록은 수입·지출 통계에 중복 반영하지 않습니다.
- 저축 기록의 수정·삭제 및 인출 처리, 목표 완료 후 관리 방식은 추후 결정합니다.

## 6. 조회 및 데이터 시각화

- 가계부 데이터를 시각화할 수 있어야 합니다.
- 가계부 내역을 **일별**, **주별**, **월별**로 조회할 수 있어야 합니다.
- 시각화 지표와 차트 종류는 추후 결정합니다.

## 7. 카테고리 관리

- 수입과 지출 카테고리를 구분합니다.
- 하위 분류 없이 1단계로 구성합니다.
- 기본 카테고리를 제공하며 사용자가 직접 추가하거나 수정할 수 있어야 합니다.
- 기존 내역에서 사용 중인 카테고리는 보관 처리하여 기존 내역을 유지하고 신규 선택에서 제외합니다.
- 기존 거래를 수정할 때 이미 연결된 보관 카테고리를 그대로 유지할 수 있습니다. 보관된 카테고리를 새 거래에 선택하거나 기존 거래에 새로 연결할 수는 없습니다.

## 8. 환불·취소 처리

- 기존 지출 내역에 연결하여 환불을 기록할 수 있어야 합니다.
- 전액 환불과 부분 환불을 지원하며, 연결된 환불 금액을 지출 집계에 반영합니다.
- 환불이 연결된 원거래를 삭제할 때는 연결된 환불도 함께 삭제된다고 확인창에 안내합니다. 사용자가 확인하면 원거래와 연결된 환불을 함께 삭제하고 관련 통계·예산 집계를 갱신합니다. 취소하면 모두 유지합니다.
- 해당 원거래가 고정지출에서 생성되었다면 회차도 '건너뜀'으로 처리하여 자동 재생성을 방지하고 이후 회차는 유지합니다.
- 원거래의 날짜·금액을 수정하려면 연결 환불을 모두 먼저 삭제해야 합니다. 환불 기록만 삭제할 수 있어야 하며, 삭제 확인 방식과 집계 갱신의 세부 규칙은 추후 결정합니다.
- 환불의 집계 기준일(원거래일/환불일), 복수 환불 및 환불 기록 자체의 수정·삭제 세부 방식은 추후 결정합니다.

## 9. 반응형 웹과 모바일 대응

- 모바일·태블릿·데스크톱 화면 너비에 맞춰 레이아웃이 조정되는 반응형 웹으로 구현합니다.
- 최소 지원 뷰포트 너비는 320 CSS px입니다.
- 320px 너비에서도 거래 입력·조회·수정·삭제, 고정지출, 환불, 예산·저축 목표, 데이터 내보내기·가져오기 등 핵심 기능을 사용할 수 있어야 합니다.
- 좁은 화면에서 콘텐츠와 조작 요소가 잘리거나 겹치지 않아야 하며, 페이지 전체의 가로 스크롤 없이 사용할 수 있도록 배치합니다.
